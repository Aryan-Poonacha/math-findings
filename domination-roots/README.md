# A graph with domination root −10

Paper: [paper.pdf](paper.pdf) (source `paper.tex`; numbers in `tables.tex` are generated by `verify.py`). Archived at [doi:10.5281/zenodo.24606431](https://doi.org/10.5281/zenodo.24606431).

New results (D(G,x) = sum of x^|S| over dominating sets S):
1. A connected 373-vertex, 673-edge graph G10 (a hub with 22 leaves and 45 attached blocks) has the simple root −10. With known results, the integers r in [−11,−1] with D(G,r) = 0 for some graph are exactly −2, −4, −6, −8, −10.
2. Roots −4, −6, −8, −10 in one connected graph with any prescribed multiplicities: MathArena's join covers −4, −6, −8 and Ma–Zhang −4 alone; −10 is the new ingredient.

Remark: an exhaustive search finds no graph on at most 12 vertices with root −4, and none on at most 11 vertices with root −6, −8 or −10. For −4 this is an independent computation agreeing with lucasxx16 (below) through order 12.

Known before (cited in the paper): odd integers are never roots (Brouwer–Csorba–Schrijver 2009); the root −4 (Alikhani–Griswold 2026); graphs with roots −6 and −8, a 15-vertex graph with root −4, support joins and the block-ratio search (MathArena, October 2026); a 30-vertex graph with root −4, and cycle-rank bounds on integer roots with the question whether −8 or −10 is a root of a graph of cycle rank two (Reshetnikov, September 2026); a 21-vertex graph and a family of orders 33r+2 with root −4 (Omega Institute, Lean); multiplicity r for −4 and every order ≥ 35 (Ma–Zhang, November 2026); no graph on at most 14 vertices has root −4, so the least order is 15 (lucasxx16, 21 November 2026, computer-assisted, not peer reviewed); the joining lemma (Kotek et al. 2012).

Check:
- `python3 -B verify.py` (default, fast: standard library only, about 1 s): G10 and Table 1, the multiplicity construction and Table 2, and the search scaled down (connected graphs through order 7, root −4 at order 8).
- `python3 -B verify.py --full NAUTY_DIR` (full, about 1 h on 15 threads; NAUTY_DIR = a built nauty 2.8.9 source tree, needs gcc): also reruns the search through order 12. It resumes from `rerun/`, reusing a slice only when the binary's sha256, the slice arguments and a complete result record match; for an independent rerun, start with no `rerun/`. The search is one C implementation (`search/`), run twice. Logs, build commands and hashes: `logs/`.
